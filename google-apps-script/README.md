# خدمة البريد الإلكتروني — تكليفات | Takleefat

نظام بريد مركزي واحد يعمل عبر **Google Apps Script + Gmail** حصراً — بلا أي خدمة بريد خارجية مدفوعة (لا SendGrid ولا Resend ولا Mailgun).

```
تطبيق تكليفات (Next.js)
   ↓  POST { secret, type, to, subject, title, lines, rows, cta }
Google Apps Script Web App (هذا المجلد — Code.gs واحد فقط)
   ↓  تحقق السر → بطاقة HTML RTL موحّدة
Gmail (MailApp)
   ↓
المستخدم
```

## خطوات الإعداد (10 دقائق)

1. **إنشاء السكربت**
   - افتح <https://script.google.com> → **New project**
   - الصق محتوى `Code.gs` كاملاً في المحرر واحفظ باسم «Takleefat Mailer»

2. **ضبط السر**
   - أنشئ سراً قوياً (32 حرفاً عشوائياً مثلاً):
     ```bash
     openssl rand -hex 32
     ```
   - ضعه في السطر `var APP_SECRET = '...'` داخل `Code.gs`
   - **نفس القيمة تماماً** ستوضع في متغيرات بيئة التطبيق (خطوة 4)

3. **النشر كـ Web App**
   - Deploy → **New deployment** → اختر النوع **Web app**
   - Description: `Takleefat mailer v1`
   - Execute as: **Me** (حسابك — ليُرسل من بريد المنصة)
   - Who has access: **Anyone** ← ضروري ليستقبل الخادم الاستدعاءات (الحماية عبر السر)
   - Deploy → وافق على الأذونات (سيطلب صلاحية Gmail — طبيعي)
   - انسخ **Web app URL** المنتهي بـ `/exec`

4. **متغيرات البيئة في التطبيق** (Vercel → Settings → Environment Variables)
   ```
   GOOGLE_APPS_SCRIPT_URL=https://script.google.com/macros/s/XXXX/exec
   GOOGLE_APPS_SCRIPT_SECRET=<نفس السر أعلاه>
   APP_URL=https://<نطاق التطبيق>        # لأزرار «عرض التفاصيل» في البريد
   ```
   ⚠️ لا تضع هذه القيم في الكود أو المستودع أبداً.

5. **اختبار الربط**
   - من لوحة الإدارة في التطبيق → «إعدادات البريد الإلكتروني» → أزرار **إعادة فحص** و**إرسال بريد تجريبي**
   - أو اختباراً مباشراً من محرر Apps Script: شغّل الدالة `sendTestMail_`

## ربط الخدمة مع Gmail

الإرسال يتم عبر دالة `MailApp.sendEmail` بحساب Google الذي نشر السكربت («Execute as: Me») — أول عملية نشر تطلب موافقة صلاحية البريد. اسم المرسل الظاهر للمستخدم هو «تكليفات». الرسائل تخرج من صندوق Gmail نفسه بلا SMTP ولا كلمات مرور تطبيقات.

## حدود الخدمة المجانية (يجب احترامها)

| البند | الحد التقريبي |
|---|---|
| Gmail العادي عبر MailApp | **~100 رسالة/يوم** |
| Google Workspace (إن وُجد) | ~1500 رسالة/يوم |
| زمن استجابة Web App | قد يصل لثوانٍ — التطبيق يعالجها بمهلة 8 ثوانٍ بلا تعطيل |

- عند بلوغ الحد يُرجع السكربت رسالة واضحة، والتطبيق يسجل الحالة `failed` في سجل الإرسال المعروض للإدارة — **دون تعطيل أي عملية أساسية**.
- الإدارة تستطيع إعادة إرسال الرسائل الفاشلة يدوياً من لوحة «إعدادات البريد الإلكتروني».
- لا إعادة إرسال تلقائي غير محدود — قرار الإعادة يدوي للإدارة حصراً.

## أنواع الإشعارات المدعومة

كل الأنواع تمر من قالب موحد (`baseEmailTemplate`) — إضافة نوع جديد = سطر واحد في `TYPE_STYLES` فقط:

رمز التحقق `EMAIL_VERIFICATION` · أمان الحساب `ACCOUNT_SECURITY` · تكليف جديد `POST_CREATED` · تحديثات التكليف `ASSIGNMENT_*` · الطلبات `APPLICATION_*` والاستدعاءات `INVITATION_*` · المستندات `DOCUMENT_*` · الاعتماد `ACCOUNT_APPROVED/REJECTED` · الارتباط `AFFILIATION_UPDATED` · تنبيهات الإدارة والأهمية والنظام · رسائل الاختبار `TEST` — وأي نوع جديد مستقبلاً.

## ملفات النظام في التطبيق

| الملف | الدور |

| `lib/email/config.ts` | الأقسام والتصنيفات والإخفاء (masking) ورابط التطبيق |
| `lib/email/gas-client.ts` | عميل الإرسال (سر + مهلة 8 ثوانٍ + لا استثناءات) |
| `lib/email/send.ts` | المُرسِل المركزي: السجل + منع التكرار + رموز التحقق + التنبيهات الأمنية |
| `lib/notifications.ts` | التكامل: كل إشعار داخلي يولّد بريداً تلقائياً بلا منطق موزّع |
| `app/api/me/email*` | إضافة/تأكيد/إعادة إرسال/إعدادات البريد للمستخدم |
| `app/api/admin/email*` | حالة الخدمة + بريد تجريبي + سجل الإرسال + إعادة الإرسال (إدارة) |
| `components/shared/email-account-card.tsx` | بطاقة البريد والإعدادات في ملفات جميع الأدوار |
| `components/admin/email-service-panel.tsx` | لوحة إعدادات البريد في لوحة الإدارة |
